# 代码审核标准

Reviewer 按下面顺序审。

## 1. 需求和规格

- 是否有关联 OpenSpec change。
- proposal 是否讲清楚为什么做。
- spec 是否可验收。
- tasks 是否完成。

## 2. 行为正确性

- 是否满足 GIVEN/WHEN/THEN。
- 是否覆盖异常分支。
- 是否保留老行为兼容。
- 是否影响已有用户。

## 3. 接口兼容

- 路径是否变更。
- 参数是否变更。
- 响应结构是否变更。
- 前端是否同步。

## 4. 权限和安全

- 是否绕过登录。
- 是否越权访问。
- 是否暴露敏感字段。
- 是否记录敏感日志。

## 5. 数据和中间件

- 事务边界是否正确。
- 缓存一致性是否处理。
- ES 索引是否需要重建。
- Kafka 消息是否幂等。
- R2/S3 文件生命周期是否明确。

## 6. 可维护性

- 命名是否清楚。
- 分层是否合理。
- 是否引入重复逻辑。
- 是否做了无关重构。

## 7. 验证和回滚

- 本地验证是否充分。
- QA 验证路径是否清楚。
- 回滚方案是否可操作。
