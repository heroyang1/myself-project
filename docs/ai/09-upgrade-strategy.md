# 基础组件升级策略

## 总原则

升级 JDK、Spring Boot、Spring Cloud、Redis、Kafka、Elasticsearch、Nacos、MySQL 等基础组件，必须按项目级 OpenSpec change 管理。

## 升级文档必须包含

- 当前版本。
- 目标版本。
- 兼容性矩阵。
- 影响模块。
- 不兼容 API。
- 配置迁移。
- 数据迁移。
- 回滚方式。
- QA 验证。
- 灰度计划。

## 推荐升级顺序

1. 补齐测试和 smoke。
2. 升级构建工具和依赖锁定。
3. 在独立分支升级非生产环境。
4. 修复编译和运行问题。
5. 做接口回归。
6. 做性能和稳定性验证。
7. 灰度发布。
8. 全量发布。

## 微服务拆分

拆分时不要先搬代码，先定义边界：

- 服务职责。
- 数据归属。
- API 契约。
- 事件契约。
- 权限模型。
- 降级策略。
- 观测指标。

没有边界的微服务，只是把单体切成一堆会互相打电话的麻烦。
