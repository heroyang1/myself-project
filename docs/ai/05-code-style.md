# 后端代码风格

## Java

- 保持现有 Java 8 兼容语法，除非升级 OpenSpec 已批准。
- 命名表达业务含义，不使用 `handleData2`、`doSomeThing` 这类名字。
- 方法长度超过 80 行时优先拆分。
- 公共方法要明确输入、输出、异常。
- 复杂判断要提取成具名方法。

## Spring Boot

- Controller 只做入口。
- Service 写业务编排。
- Mapper 只做数据库访问。
- 事务放在 Service 层。
- 配置类不写业务逻辑。
- 定时任务必须说明幂等和并发控制。

## API

- 新接口路径优先按业务域设计。
- 不破坏已有 `/pc/**` 路径兼容。
- 响应结构保持统一包装。
- 错误信息要能定位问题，但不能泄露敏感信息。

## 日志

- 关键业务失败要有日志。
- 日志要带业务 ID，例如 userId、orderId、courseId。
- 不打印密码、token、密钥、完整手机号等敏感信息。

## 配置

- 生产配置不得写死在代码。
- 新增配置必须说明默认值和环境差异。
- 中间件连接信息必须走配置中心或环境变量。
