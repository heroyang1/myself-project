## 2. 功能流程梳理

### 2.1 浏览与搜索流程

1. 前端先调用 `GET /pc/website/tags` 获取标签候选。
2. 再调用 `POST /pc/website/list` 查询网站列表。
3. 列表查询优先走 ES；ES 无结果或异常时，降级到 MySQL。
4. 若请求携带有效 `token`，过滤器即使面对 `@Anonymous` 接口，也会解析 token 并写入用户上下文，列表结果会额外回填 `myRatingType`。
5. 用户点击网站后，前端调用 `PUT /pc/website/click?id=xxx` 递增点击数。
6. 页面可额外调用 `GET /pc/website/notices` 和 `GET /pc/website/dynamics` 获取公告栏与动态栏。

### 2.2 用户提交网站流程

1. 调用 `POST /pc/website/submit` 提交单个网站。
2. Service 校验 `name`、`url` 非空，且 `url` 必须以 `http://` 或 `https://` 开头。
3. 提交接口带分布式锁：`scene=website_submit`、`key=website_submit_lock`、`includeUserId=true`。
4. 网站主表插入时状态固定为 `2-待审核`。
5. 若带 `tagNames`，系统会自动清洗去重、自动创建不存在的标签、建立标签关联、增加标签 `use_count`。
6. 提交后会尝试发送邮件通知；邮件失败不影响主流程。
7. 提交成功后进入审核队列。

### 2.3 Excel 导入流程

1. 先调用 `GET /pc/website/import/template` 下载模板。
2. 模板列固定为：
   - `网站名称`
   - `网站链接`
   - `网站描述`
   - `Logo地址`
   - `标签(多个用英文逗号分隔)`
3. 上传时使用 `multipart/form-data`，文件字段名固定为 `file`。
4. 普通用户调用 `POST /pc/website/import`：
   - 导入后状态为 `2-待审核`
   - 进入审核列表
5. 管理员调用 `POST /pc/website/import/admin`：
   - 导入后状态为 `4-已发布`
   - 成功写库后会尝试同步到 ES
6. 导入内部流程：
   - 读取第一个 sheet
   - 表头按 `WebsiteImportDTO` 映射
   - 单次最多 500 行
   - 行级校验：名称、链接、URL 前缀、长度
   - Excel 内 URL 去重
   - 数据库 URL 去重
   - 插入网站主表
   - 绑定标签
7. 返回结果为 `WebsiteImportResultVO`，包含成功数、失败数、失败明细。

### 2.4 审核发布流程

1. 管理端调用 `GET /pc/website/audit/list` 查询待审核列表。
2. 理论上再调用 `GET /pc/website/audit/detail/{websiteId}` 查询详情。
3. 最后调用 `POST /pc/website/audit` 进行通过或拒绝。
4. 当前审核接口真实接受的状态值是：
   - `4`：审核通过
   - `6`：审核拒绝
5. 拒绝时会写入 `rejectReason`。
6. 审核通过后当前 Service 会更新状态、审核人、审核时间。
7. 当前这条控制器链路里没有直接写公告栏。
8. 当前这条控制器链路里的 ES 同步条件存在状态值不一致问题，审核通过后通常不会经由该接口同步到 ES。

## 3. 认证与权限

### 3.1 认证方式

#### 3.1.1 公开接口

当前带 `@Anonymous` 的接口包括：

- `GET /pc/website/notices`
- `GET /pc/website/dynamics`
- `GET /pc/website/tags`
- `POST /pc/website/list`
- `PUT /pc/website/click`
- `GET /pc/website/import/template`
- `POST /pc/website/import`
- `POST /pc/website/import/admin`
- `GET /pc/homepage/website/hot`
- `POST /pc/website/es/recreateIndex`
- `POST /pc/website/es/syncAll`

#### 3.1.2 `@Anonymous` 接口的 token 行为

- 当前前台认证过滤器对 `@Anonymous` 接口也会尝试解析 `token`。
- 若 `token` 有效，仍会写入 ThreadLocal 用户上下文。
- 若 `token` 缺失或失效，不会返回 401，而是按匿名请求放行。

这意味着：

- `POST /pc/website/list` 这类接口可以匿名访问，但带有效 `token` 时能拿到更多个性化字段。
- `POST /pc/website/import` 和 `POST /pc/website/import/admin` 虽然注解上是匿名，但方法内部直接调用 `getCurrentUser()` 取操作人，因此实际仍应携带有效 `token`，否则大概率返回通用失败消息。

#### 3.1.3 需要登录的接口

以下接口依赖有效登录态：

- `POST /pc/website/submit`
- `POST /pc/website/favorite`
- `GET /pc/website/del`
- `GET /pc/website/Favorites`
- `POST /pc/website/rating/submit`
- `POST /pc/website/audit`
- `GET /pc/website/audit/list`
- `GET /pc/website/audit/detail/{websiteId}`
- `GET /pc/website/batch`

未登录或 token 失效时，认证层通常返回：

```json
{
  "code": 401,
  "msg": "未登录或Token已过期"
}
```

### 7.4 查询网站列表

- 方法：`POST`
- 路径：`/pc/website/list`
- 认证：匿名
- 请求体：JSON

请求示例：

```json
{
  "websiteName": "Git",
  "tagNames": ["后端", "代码托管"],
  "pageNum": 1,
  "pageSize": 10
}
```

真实流程：

1. 优先查 ES。
2. ES 命中后，回填 MySQL 中最新的 `goodCount`、`midCount`、`badCount`。
3. 若当前请求带有效 `token`，再回填 `myRatingType`。
4. ES 异常或无结果时，降级到 MySQL。

查询语义：

- ES：`websiteName` 同时搜 `name` 和 `description`
- ES：标签使用 `termsQuery(tags, tagNames)`，语义是“命中任一标签”
- MySQL：`websiteName` 只对 `w.name LIKE`
- MySQL：标签条件是 `t.tag_name IN (...)`，同样是“命中任一标签”

MySQL 路径查询范围：

- `delete_flag = 0`
- `status = 4`

## 8. 用户交互与导入接口

基础路径：`/pc/website`

### 8.1 提交网站

- 方法：`POST`
- 路径：`/pc/website/submit`
- 认证：登录
- 权限：`website:submit`

请求体示例：

```json
{
  "name": "Hugging Face",
  "url": "https://huggingface.co",
  "description": "AI 模型与数据集平台",
  "logoUrl": "https://huggingface.co/front/assets/huggingface_logo.svg",
  "tagNames": ["AI", "模型平台"]
}
```

校验规则：

1. `name` 和 `url` 不能为空
2. `url` 必须以 `http://` 或 `https://` 开头

真实行为：

1. 生成资源编号 `no`
2. 状态写为 `2-待审核`
3. 标签不存在时自动创建
4. 绑定标签并增加标签使用次数
5. 尝试发送通知邮件

### 8.2 收藏网站

- 方法：`POST`
- 路径：`/pc/website/favorite`
- 认证：登录
- 权限：`website:favorite`

请求参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `websiteId` | Long | 是 | 网站 ID |
| `remark` | String | 否 | 收藏备注，当前不会真正保存 |

真实行为：

1. 校验当前用户是否已收藏
2. 已收藏则报错
3. 调用网站表 `collection_count + 1`
4. 收藏表使用 `ON DUPLICATE KEY UPDATE delete_flag = 0`

注意：

- 当前实现没有显式校验网站是否存在或是否已发布。
- 若 `websiteId` 不属于 `status = 4` 的网站，收藏记录仍可能写入，但网站收藏数不会增加。

### 8.3 取消收藏

- 方法：`GET`
- 路径：`/pc/website/del`
- 认证：登录
- 权限：`website:favorite:cancel`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `websiteId` | Long | 是 | 网站 ID |

真实行为：

1. 校验当前用户已收藏
2. 网站表 `collection_count - 1`
3. 收藏记录软删除 `delete_flag = 1`

### 8.4 我的收藏列表

- 方法：`GET`
- 路径：`/pc/website/Favorites`
- 认证：登录
- 权限：`website:favorite:list`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pageNum` | Integer | 否 | 页码，默认 1 |
| `pageSize` | Integer | 否 | 页大小，默认 10 |

说明：

- 路径中的 `Favorites` 首字母大写，前端调用要保持一致。
- 排序为 `favorite_time desc`。

### 8.5 提交网站评价

- 方法：`POST`
- 路径：`/pc/website/rating/submit`
- 认证：登录
- 权限：`website:rating:submit`
- 请求体：JSON

请求示例：

```json
{
  "websiteId": 1,
  "ratingType": 1
}
```

校验规则：

1. `websiteId` 不能为空
2. `ratingType` 不能为空
3. `ratingType` 必须在 `1/2/3` 内
4. 网站必须满足 `status = 4`

真实行为：

- 第一次评价：新增评价记录、更新网站计数、同步 ES 评价计数
- 修改评价：若新旧值相同则报错；不同则更新记录与计数，再同步 ES
- 好评时会写动态栏

### 8.6 普通用户 Excel 导入

- 方法：`POST`
- 路径：`/pc/website/import`
- 认证：控制器标注匿名，但实际应携带有效 `token`
- 设计权限：`website:import`，当前未启用
- 请求体：`multipart/form-data`

表单参数：

| 参数 | 类型 | 必填 | 说明 |

| `file` | File | 是 | Excel 文件 |

导入规则：

2. 只读取默认 sheet

4. 网站名称不能为空
5. 网站链接不能为空
6. 链接必须以 `http://` 或 `https://` 开头
7. 网站名称长度不能超过 100
8. 网站链接长度不能超过 500
9. 文件内 URL 重复时跳过
10. 数据库内 URL 已存在时跳过
11. 标签列按英文逗号拆分

导入后行为：

1. 网站状态写为 `2-待审核`

3. 不会直接同步 ES

## 9. 管理审核接口

基础路径：`/pc/website`

### 9.1 审核网站

- 方法：`POST`
- 路径：`/pc/website/audit`
- 认证：登录
- 权限：`website:audit`
- 请求体：JSON

通过示例：

```json
{
  "websiteId": 20,
  "status": 4
}
```

拒绝示例：

```json
{
  "websiteId": 20,
  "status": 6,
  "rejectReason": "网站内容不符合规范"
}
```

真实规则：

1. `websiteId` 不能为空
2. `status` 只能是 `4` 或 `6`
3. 拒绝时 `rejectReason` 必填
4. 待审核判断使用 `status = 2`

通过后的当前行为：

1. 更新状态为 `4`
2. `auditBy` 固定写死为 `admin`
3. `auditTime` 写当前时间
4. 当前这条接口链路不会直接写公告栏
5. 代码意图是同步 ES，但查询条件写成了 `status = 1`，因此该链路通常拿不到刚审核通过的数据

拒绝后的行为：

1. 更新状态为 `6`
2. 写入 `rejectReason`

## 12. 当前实现注意事项

### 12.1 状态口径并不完全统一

- 主链路使用 `2/4/6`
- 首页热门仍查 `status = 1`
- 审核详情仍查 `status = 0`

### 12.2 审核通过链路存在 ES 同步缺口

- `POST /pc/website/audit` 在审核通过后，读取 `status = 1` 的数据尝试同步 ES。
- 但主链路发布态实际是 `4`，因此这一段通常查不到数据。

### 12.3 审核接口本身不会直接写公告栏

- 当前 `OshPracticalWebsiteServiceImpl.auditWebsite()` 只更新状态与审核信息。
- 仓库里另有 `WebsiteResourceAuditCallbackHandler` 具备“审核通过写公告栏”的能力，但并不在这条控制器链路中直接触发。

### 12.4 导入接口注解匿名，但实现依赖登录上下文

- `POST /pc/website/import`
- `POST /pc/website/import/admin`

这两个接口虽然用了 `@Anonymous`，但内部直接 `getCurrentUser()` 获取操作人，因此联调时应当带有效 `token`。

### 12.5 收藏备注 `remark` 当前无效

- 控制器暴露了 `remark`
- 列表 VO 也有 `remark`
- 但当前收藏写库 SQL 并未保存该字段

### 12.6 删除后不会自动修正 ES 与标签使用次数

- 批量删除不会删 ES 文档
- 批量删除不会减少标签 `use_count`

### 12.7 网站主表插入列较少

`insertWebsite` 当前只插入：

- `no`
- `name`
- `url`
- `description`
- `logo_url`
- `status`

这意味着：

- Service 中设置的部分字段依赖数据库默认值
- `createBy`、导入时的 `auditBy`、`auditTime` 等并不会在新建记录时完整落库
