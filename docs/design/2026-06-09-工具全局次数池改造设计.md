# 工具全局次数池改造设计

## 1. 背景

当前工具模块的次数体系按 `user_id + tool_id` 维度存储在 `osh_tool_user_quota` 中，同一用户针对不同工具会产生多条额度记录。工具购买链路依赖 `osh_tool_package` 工具套餐表，支付成功后将次数发放到指定工具，再由工具使用链路按工具维度扣减。

该模型存在以下问题：

1. 用户次数被拆散在多个工具下，无法形成统一余额。
2. 新增工具必须补齐工具套餐和购买逻辑，接入成本高。
3. 工具售卖与工具使用强耦合，后续无法快速演进为平台统一充值体系。

本次改造目标是将工具次数体系调整为“用户全局次数池”模型：每个用户仅保留一条次数记录，平台统一售卖全局次数套餐，所有需要扣次的工具都从同一个余额中消费。

## 2. 目标

### 2.1 业务目标

1. 每个用户在次数表中仅保留一条全局次数记录。
2. 平台不再售卖工具套餐，只售卖全局次数套餐。
3. 所有工具按自身使用规则从全局余额中扣减次数。
4. 工具详情仍可展示当前用户剩余次数，但该值为全局余额。
5. 历史工具购买记录保留，不要求清洗为新结构。

### 2.2 非目标

1. 本次不改 `backstage-ui` 模块。
2. 本次不处理历史购买记录页面的前端展示兼容。
3. 本次不引入多种余额池，如“工具次数”“AI次数”“视频次数”等分类额度。
4. 本次不执行数据库变更，只提供 SQL 草案与落库方案。

## 3. 现状分析

### 3.1 当前关键表

1. `osh_tool_user_quota`
   - 当前语义：用户针对某个工具的次数余额。
   - 当前主维度：`user_id + tool_id`。

2. `osh_tool_package`
   - 当前语义：工具售卖套餐。
   - 当前主维度：`tool_id` 关联工具。

3. `osh_tool_purchase_record`
   - 当前语义：工具购买记录。
   - 当前记录中包含工具快照、工具套餐快照。

4. `osh_tool`
   - 当前语义：工具主表。
   - 当前仍参与“是否售卖/是否展示套餐/是否检查购买次数”的逻辑判断。

### 3.2 当前关键代码链路

1. 工具购买详情
   - `ToolPurchaseController#detail`
   - `ToolPurchaseServiceImpl#getPurchaseDetail`
   - 当前依赖 `toolId` 查询工具信息和工具套餐列表。

2. 工具下单
   - `ToolPurchaseController#create`
   - `ToolPurchaseServiceImpl#createPurchaseOrder`
   - 当前依赖 `toolId + packageId` 校验工具与工具套餐关系。

3. 支付成功发放次数
   - `ToolPaidHandler#handle`
   - 当前将次数发放到 `osh_tool_user_quota` 的指定 `tool_id`。

4. 工具使用扣次
   - `OshToolServiceImpl#consumeToolUsage`
   - `OshToolServiceImpl#checkToolUsagePermission`
   - 当前从 `osh_tool_user_quota` 按 `toolId` 查询和扣减。

## 4. 目标模型设计

### 4.1 用户全局次数表

沿用表名 `osh_tool_user_quota`，但将语义调整为“用户全局工具次数表”。

#### 目标字段

1. `id`
2. `user_id`
3. `remaining_count`
4. `total_buy_count`
5. `used_count`
6. `last_use_time`
7. `create_by`
8. `create_time`
9. `update_by`
10. `update_time`
11. `delete_flag`

#### 字段调整

1. 废弃 `tool_id`
2. 新增或确保唯一索引：`uk_user_id(user_id)`

#### 新语义说明

1. `remaining_count`：当前用户全局可用次数
2. `total_buy_count`：当前用户累计购买次数
3. `used_count`：当前用户累计消耗次数
4. `last_use_time`：最近一次工具扣次时间

### 4.2 全局次数套餐表

新增表 `osh_global_quota_package`，替代 `osh_tool_package` 的平台售卖职责。

#### 建议字段

1. `id`
2. `package_name`
3. `use_count`
4. `price`
5. `point_cost`
6. `pay_type`
7. `status`
8. `sort_order`
9. `create_by`
10. `create_time`
11. `update_by`
12. `update_time`
13. `delete_flag`

#### 说明

1. `pay_type` 延续现有逻辑，仅保留 `1-现金`、`3-现金+积分`
2. 套餐不绑定 `tool_id`
3. 排序和启停逻辑沿用工具套餐现有设计

### 4.3 全局次数购买记录表

新增表 `osh_global_quota_purchase_record`，替代 `osh_tool_purchase_record` 的新增写入职责。

#### 建议字段

1. `id`
2. `order_no`
3. `payment_no`
4. `user_id`
5. `package_id`
6. `package_name_snapshot`
7. `package_use_count_snapshot`
8. `package_cash_amount_snapshot`
9. `package_point_amount_snapshot`
10. `package_pay_type_snapshot`
11. `order_status`
12. `grant_status`
13. `grant_time`
14. `remark`
15. `create_by`
16. `create_time`
17. `update_by`
18. `update_time`
19. `delete_flag`

#### 说明

1. 不再记录 `tool_id`
2. 不再记录 `tool_name_snapshot`
3. 保留套餐快照，确保下单后即使套餐被修改，订单记录仍可回溯

### 4.4 工具访问与扣次规则

`osh_tool` 不强制改结构，但业务语义要调整：

1. 工具是否可用，仍先按工具权限和资源类型判断。
2. 工具是否扣次，由工具自身资源类型或后续新增配置控制。
3. 扣次时不再关注购买了哪个工具，只关注用户是否存在全局剩余次数。

#### 建议原则

1. 免费工具：允许使用，不扣全局次数。
2. 扣次工具：允许使用，扣减全局次数。
3. 权限工具：先校验用户等级或其他权限，再决定是否允许使用与是否扣次。

## 5. 数据迁移方案

### 5.1 次数表迁移

迁移目标：将旧 `osh_tool_user_quota` 聚合为按用户唯一的一条记录。

#### 聚合规则

1. `remaining_count = sum(remaining_count)`
2. `total_buy_count = sum(total_buy_count)`
3. `used_count = sum(used_count)`
4. `last_use_time = max(last_use_time)`

#### 推荐策略

1. 新建 `osh_tool_user_quota_new`
2. 将旧表数据聚合插入新表
3. 代码切换到新表结构或重命名替换
4. 保留旧表做回滚兜底，确认稳定后再处理历史表

### 5.2 工具套餐迁移

`osh_tool_package` 不建议直接原地改造，推荐：

1. 新建 `osh_global_quota_package`
2. 按业务需要挑选部分历史工具套餐初始化为平台全局套餐
3. 初始化时人为确认套餐名称、价格和次数，不直接全量迁移所有工具套餐

原因：

1. 旧工具套餐存在工具特定语义，直接迁移会带入冗余历史数据
2. 平台全局套餐通常会重新设计，不一定等于某个工具原有套餐

### 5.3 购买记录迁移

1. 旧 `osh_tool_purchase_record` 保留历史查询用途
2. 新增订单写入 `osh_global_quota_purchase_record`
3. 不强制将旧记录重刷为新结构

原因：

1. 旧订单本身是工具购买语义，强行迁移会造成语义失真
2. 保留双表可以降低切换风险

## 6. 接口与服务改造设计

### 6.1 全局次数购买详情接口

当前接口：`GET /pc/tool/purchase/detail?toolId=xxx`

建议改为：

1. 保持原路径，去掉 `toolId` 入参，返回平台全局次数购买详情
2. 或新增平台化路径，例如 `/pc/tool/quota/detail`

返回内容建议：

1. 当前用户全局剩余次数
2. 全局次数套餐列表

不再返回：

1. 工具名称
2. 工具描述
3. 某个工具的剩余次数

### 6.2 全局次数下单接口

当前请求对象依赖：

1. `toolId`
2. `packageId`
3. `payType`
4. `channel`

建议改为：

1. 去掉 `toolId`
2. 保留 `packageId`
3. 保留 `payType`
4. 保留 `channel`

### 6.3 购买记录列表接口

建议去掉按 `toolId` 过滤能力，改为查询全局次数购买记录。

### 6.4 支付成功回调发放

支付成功后：

1. 按订单中的 `package_use_count_snapshot` 发放到用户全局次数表
2. 更新全局购买记录发放状态
3. 不再关注工具 ID

### 6.5 工具扣次接口

当前入参 `ToolUsageConsumeRequest` 仍保留 `toolId` 是合理的，因为扣次动作依然由“使用某个工具”触发。

但底层处理调整为：

1. 通过 `toolId` 找到工具并校验是否允许使用
2. 如果该工具不需要扣次，直接返回
3. 如果该工具需要扣次，则从全局次数表按 `user_id` 扣减

## 8. 风险与控制

### 8.1 数据口径变化风险

风险：工具详情页的“剩余次数”从工具级变为全局级，展示口径变化。

控制：

1. 后端接口字段名可暂不变，但在文档中明确其语义已调整为全局剩余次数。
2. 如后续需要，可新增更清晰的字段名，例如 `globalRemainingCount`。

### 8.2 历史订单查询风险

风险：旧工具订单和新全局次数订单分散在两张表中。

控制：

1. 本次先保证新增链路正确
2. 如需统一订单记录页，可在后续增加聚合查询层

### 8.3 切换期间数据双写风险

风险：如果代码和表结构切换不彻底，可能出现旧表与新表混写。

控制：

1. 先落新表和新代码
2. 发版时统一切走购买与发放逻辑
3. 切换完成后停用旧购买入口的写入能力

## 9. 推荐实施顺序

1. 新建设计文档与实施计划
2. 编写 SQL 草案
3. 新增全局套餐与全局购买记录领域模型、Mapper、XML
4. 改造全局次数购买链路
5. 改造支付成功发放链路
6. 改造工具详情次数查询与工具扣次链路
7. 补齐测试

## 10. SQL 草案

### 10.1 新建全局次数套餐表

```sql
CREATE TABLE `osh_global_quota_package` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `package_name` varchar(100) NOT NULL,
  `use_count` int NOT NULL,
  `price` decimal(10,2) NOT NULL DEFAULT '0.00',
  `point_cost` int NOT NULL DEFAULT '0',
  `pay_type` tinyint NOT NULL COMMENT '1-现金，3-现金+积分',
  `status` tinyint NOT NULL DEFAULT '1',
  `sort_order` int NOT NULL DEFAULT '0',
  `create_by` varchar(64) DEFAULT '',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_by` varchar(64) DEFAULT '',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `delete_flag` tinyint NOT NULL DEFAULT '0',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs COMMENT='全局次数套餐表';
```

### 10.2 新建全局次数购买记录表

```sql
CREATE TABLE `osh_global_quota_purchase_record` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `order_no` varchar(64) NOT NULL,
  `payment_no` varchar(64) DEFAULT NULL,
  `user_id` bigint NOT NULL,
  `package_id` bigint NOT NULL,
  `package_name_snapshot` varchar(100) NOT NULL,
  `package_use_count_snapshot` int NOT NULL,
  `package_cash_amount_snapshot` decimal(10,2) NOT NULL DEFAULT '0.00',
  `package_point_amount_snapshot` int NOT NULL DEFAULT '0',
  `package_pay_type_snapshot` tinyint NOT NULL,
  `order_status` tinyint NOT NULL DEFAULT '0',
  `grant_status` tinyint NOT NULL DEFAULT '0',
  `grant_time` datetime DEFAULT NULL,
  `remark` varchar(255) DEFAULT NULL,
  `create_by` varchar(64) DEFAULT '',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_by` varchar(64) DEFAULT '',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `delete_flag` tinyint NOT NULL DEFAULT '0',
  PRIMARY KEY (`id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_order_no` (`order_no`),
  KEY `idx_payment_no` (`payment_no`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs COMMENT='全局次数购买记录表';
```

### 10.3 新建全局次数余额表

```sql
CREATE TABLE `osh_tool_user_quota_new` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `user_id` bigint NOT NULL,
  `remaining_count` int NOT NULL DEFAULT '0',
  `total_buy_count` int NOT NULL DEFAULT '0',
  `used_count` int NOT NULL DEFAULT '0',
  `last_use_time` datetime DEFAULT NULL,
  `create_by` varchar(64) DEFAULT '',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_by` varchar(64) DEFAULT '',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `delete_flag` tinyint NOT NULL DEFAULT '0',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs COMMENT='用户全局工具次数表';
```

### 10.4 聚合迁移旧次数数据

```sql
INSERT INTO osh_tool_user_quota_new (
  user_id,
  remaining_count,
  total_buy_count,
  used_count,
  last_use_time,
  create_by,
  create_time,
  update_by,
  update_time,
  delete_flag
)
SELECT
  user_id,
  SUM(remaining_count) AS remaining_count,
  SUM(total_buy_count) AS total_buy_count,
  SUM(used_count) AS used_count,
  MAX(last_use_time) AS last_use_time,
  'system' AS create_by,
  NOW() AS create_time,
  'system' AS update_by,
  NOW() AS update_time,
  0 AS delete_flag
FROM osh_tool_user_quota
WHERE delete_flag = 0
GROUP BY user_id;
```
