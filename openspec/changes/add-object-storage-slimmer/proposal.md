# Proposal: add-object-storage-slimmer

## 背景

课程视频和对象存储文件会持续增长，生产与测试曾共用 `osh` 桶，存在测试误操作影响生产资源的风险。主站需要在后台管理中查看对象存储文件瘦身状态，并通过 XXL-JOB 定时对视频做保守压码率处理，降低 R2 占用，同时确保不误删、不影响已有播放链路。

## 目标

- 新增对象存储瘦身任务表，记录每个对象的扫描、备份、转码、验证、覆盖、回滚和失败状态。
- 新增管理接口：概览、分页、手动扫描/瘦身、启停定时瘦身开关、重试、回滚、删除备份。
- 新增 XXL-JOB handler `osh-object-storage-slimmer`，由调度触发批量扫描和瘦身。
- 瘦身前先复制原文件到备份桶，备份桶默认是原桶名拼接 `-backup`，不存在则创建。
- 默认覆盖原 key 并保留备份 key，不更新课程视频 URL，从而不影响现有播放链路。
- 默认不降分辨率，只压码率；仅当新文件可播放、时长接近且体积至少下降阈值时覆盖原对象。
- 测试环境对象桶改为 `osh-qa`，避免继续与生产共用 `osh`。

## 非目标

- 本次不做自动删除备份文件。备份只能由管理员在确认瘦身后视频可播放时手动删除。
- 本次不直接调用 XXL-JOB Admin 修改调度配置；后台启停只控制 XXL-JOB 定时触发，关闭时 handler 立即退出；手动瘦身仍可用于灰度验证。
- 本次不处理图片/文档压缩，只展示其他文件并标记为不支持/跳过。
- 本次不引入 ffmpeg wasm 到主站后端或前端。

## 用户影响

- 管理员可以在主站 Nuxt 后台查看对象存储中文件和视频瘦身状态。
- 管理员可以手动触发扫描、瘦身、重试、回滚和删除备份。
- 已有课程播放仍使用原对象 key，瘦身成功后无需改 DB 中的 `media_url`。
- 若转码失败、校验失败或节省不足，原视频不被覆盖。

## 风险

- 兼容性风险：中。新增 R2 copy/list/head/put/delete 操作，需要与 Cloudflare R2 S3 兼容行为对齐。
- 数据风险：中。覆盖原 key 前必须先备份和验证，失败时保持原文件不变。
- 性能风险：中。ffmpeg 转码消耗 CPU、临时磁盘和内存，需限制批量数量和并发。
- 安全风险：中。删除备份是不可逆操作，必须只允许管理员手动触发。
- 回滚风险：中。可以通过备份桶 key 回滚对象内容；代码回滚后任务表可保留。

## 验收标准

- [ ] 测试环境 R2 bucket 使用 `osh-qa`，不再写入生产 `osh`。
- [ ] 管理员页面可以查看当前桶、备份桶、任务统计和文件列表。
- [ ] 手动扫描能把 R2 视频对象登记为任务。
- [ ] 后台开关关闭时 XXL-JOB 触发直接退出，手动瘦身仍可小批量验证。
- [ ] 瘦身前会创建/使用 `<bucket>-backup` 并复制原文件。
- [ ] 只有 ffprobe 校验通过、时长差在阈值内且体积下降达到阈值时才覆盖原 key。
- [ ] 覆盖后任务记录展示原大小、新大小、节省比例、备份 key 和状态。
- [ ] 失败任务记录失败原因，且不删除原对象和备份对象。
- [ ] 成功任务可生成预览 URL；管理员确认后可手动删除备份。
- [ ] 回滚操作可将备份对象复制回原 key，并更新任务状态。
