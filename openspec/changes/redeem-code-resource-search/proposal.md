# Proposal: redeem-code-resource-search

## 背景

核销码用于处理平台外转账或其他平台购买后的权益发放。当前后台创建核销码时依赖资源编号，但资源编号通常不在前端展示，level>=5 的核心开发者和消费者都更容易识别资源名称。核销码生成后本项目暂不做站内发送，由管理员通过平台外方式发送给消费者。

## 目标

- 后台创建核销码时支持按资源类型和资源名称搜索资源。
- 选中资源后由系统内部回填资源编号，创建接口仍复用现有 `resourceNo` 校验与发放链路。
- 增加资源搜索所需索引，提升按名称搜索和按编号定位效率。
- 创建核销码不预绑定消费者，用户中心使用时只校验是否未使用、未作废，并在核销成功后绑定当前用户。
- 用户中心与后台对外统一使用“核销码”命名，不暴露资源编号作为默认展示字段。
- 每个核销码生成一条一一对应的核销邀请链接，用于外部平台商品购买后的注册引导与核销码领取。
- 未注册用户通过核销邀请链接注册时，邮件模板同时发送唯一标识和核销码；已注册用户登录后跳转用户中心手动确认核销。

## 非目标

- 本次不接入专栏资源。
- 本次不做站内发送或自动核销。

## 用户影响

- level>=5 用户可在后台按“资源类型 + 资源名称”选择课程、电子书、工具、会员套餐生成核销码。
- 普通消费者在用户中心手动输入平台外获得的核销码，不需要理解资源编号。
- 消费者可打开管理员提前生成的核销邀请链接；未注册时完成邀请注册并通过邮件收到唯一标识与核销码，已注册时登录后进入用户中心核销码页。
- 既有核销码数据继续可读，历史 `resource_no` 仍作为内部关联字段保留。

## 风险

- 兼容性风险：低。新增资源搜索接口，创建核销码接口入参保持 `resourceNo`。
- 数据风险：中低。新增索引、邀请链接表，并将 `osh_redeem_code.user_id` 调整为可空以支持待核销码不预绑定用户。
- 性能风险：低。搜索接口分页，资源名称和编号增加辅助索引。
- 安全风险：低。资源搜索接口限制 `@OshUserLevel(5)`。
- 回滚风险：revert 代码即可；新增索引可保留或按需删除。

## 验收标准

- [ ] `POST /pc/admin/redeem/resource/search` 可按资源类型和名称返回候选资源。
- [ ] 后台创建核销码时前端不要求手填资源编号。
- [ ] 用户中心不显示“兑换码”命名，不默认展示资源编号。
- [ ] 每个核销码有唯一 `link_token`，邀请链接可解析为资源信息，登录后可解析出核销码。
- [ ] 带核销邀请链接的注册邮件同时包含唯一标识和核销码。
- [ ] `sql/2026/06/redeem_code.sql` 包含核销码表和新增索引迁移。
- [ ] 后端构建、前端生成通过。
