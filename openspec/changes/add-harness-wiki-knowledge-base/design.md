# Design: add-harness-wiki-knowledge-base

## 方案概览

纯文档变更：新建 `.harness/wiki/` 五文件（业务模型/接口协议/数据模型/领域术语/事故复盘），
每文件首行"装载时机"；内容全部锚定实扫代码事实（枚举值、控制器路径、实体字段类型）与
既有 docs/ 正文（wiki 只做摘要+指针，防双源）。ROUTING 表 1 与 CLAUDE.md 第 3 层同步登记，
宪法命名口径段压缩为"三铁律+指针"。

## 现状分析

- 相关模块：`.harness/`（wiki 目录为新建）、根 `CLAUDE.md`、`.harness/ROUTING.md`
- 相关类/接口：无代码改动；wiki 内容引用 `OrderStatusEnum`、`PaymentStatusEnum`、
  `OshFlashsaleListController` 等实扫结果
- 当前数据结构：无变化
- 当前配置：CLAUDE.md 实测 100 行（贴线）；ROUTING.md 66 行（预算 150 内）

## 详细设计

### 接口设计

| Method | Path | 变化 | 兼容策略 |
|---|---|---|---|
| 无 | 无 | 不涉及任何接口 | 不适用 |

### 数据设计

| 表/索引/缓存 | 变化 | 迁移方式 | 回滚方式 |
|---|---|---|---|
| 无 | 无 | 不适用 | 删除 wiki 目录与索引改动 |

### 文件结构与分工

```
.harness/wiki/
├── 业务模型.md    §1身份边界 §2三主链路 §3双枚举撞号 §4库存三段式 §5金额 §6快照 §7事务边界 §8状态机索引
├── 接口协议.md    §1返回格式 §2路径公约 §3认证双体系 §4域接口清单 §5回调契约 §6错误码指针
├── 数据模型.md    §1表公约 §2逻辑删除双保障 §3核心表关系 §4字段语义 §5索引纪律 §6DDL流程
├── 领域术语.md    §1通用≠项目对照表(14词+代码证据) §2双名漂移登记 §3命名口径细则(宪法迁入) §4同名消歧7组
└── 事故复盘.md    §1 A-01~A-12编号禁令(映射案例集) §2晋升流程 §3家族索引
```

双源防线：各文件头声明"正文事实源在 docs/，本文只做装载式摘要+指针"；
事故复盘不复制案例正文；错误码/索引细则均为指针。

### 中间件影响

- Redis / Kafka / Elasticsearch / Nacos / R2/S3：无（文档中提及均为描述性引用）

## 兼容性

- 老接口是否保留：不适用
- 老数据是否可读：不适用
- 前端是否需要同步：否
- 灰度期间新旧版本是否兼容：不适用；CLAUDE.md 命名口径压缩保留全部三铁律语义，
  仅迁出细节词条（唯一新住所=领域术语.md），无信息丢失

## 测试计划

- 单元测试 / 集成测试 / 接口 smoke：不适用
- 回归范围：`bash scripts/verify-ai-process.sh`；CLAUDE.md 行数 ≤100；ROUTING ≤150；
  五文件"装载时机"行存在；wiki 内引用路径 Test-Path 全通过

## 发布与回滚

- 发布步骤：随 PR 合入即生效
- 验证命令：见测试计划
- 回滚步骤：revert 本 change 提交
