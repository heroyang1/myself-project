# Proposal: add-harness-wiki-knowledge-base

## 背景

课程第 32~34 讲"上下文工程三件套"确定：知识库分层是按需加载的前提（不分层只能整包丢，
注意力被稀释）。本仓库五层知识（业务模型/接口协议/数据模型/领域术语/事故复盘）内容散落在
docs/、代码与宪法中，无统一装载入口；领域术语层最薄（寄生在宪法命名口径段），
双名域（flashsale/seckill、group/servergroup）与 order/payment 双枚举撞号等词义陷阱无独立登记处。

## 目标

- 建 `.harness/wiki/` 五层知识库（每层一个文件，开头一行"装载时机"）
- 领域术语.md 重点收录"项目含义与通用含义不一致"的词（对照表+代码证据+双名漂移登记+消歧清单）
- ROUTING.md 表 1 登记五层任务路由；CLAUDE.md 第 3 层加 1 行 wiki 索引
- CLAUDE.md 命名口径段指针化压缩（词条迁 wiki，宪法留三铁律），保持 ≤100 行

## 非目标

- 不改任何代码/配置/DDL（纯文档）
- 不改存量别名路径（/pc/order/flashsale 等，收敛须另立 change）
- 不复制案例集正文（事故复盘层只登记编号+一句话禁令+指针）

## 用户影响

- 无终端用户影响；开发者与 AI 获得"任务类型→知识层"的精确装载路径（五步定位法第 1/3 步落地）。

## 风险

- 兼容性风险：无。
- 数据风险：无。
- 性能风险：无。
- 安全风险：无（文档不含密钥/端点凭据）。
- 回滚风险：删除 wiki 目录与索引改动即完全回滚。
- 双源风险：wiki 与 docs/ 正文分工已在各文件头声明（摘要+指针，正文住 docs/），
  宪法命名口径压缩后词条唯一住所为 领域术语.md。

## 验收标准

- [ ] `.harness/wiki/` 五文件齐全，每个首行含"装载时机"
- [ ] 领域术语.md 含通用≠项目对照表与代码证据列
- [ ] CLAUDE.md ≤100 行且新增 wiki 索引行
- [ ] ROUTING.md 表 1 新增五层路由行（≤150 行）
- [ ] 各文件内引用路径真实存在（无悬空指针）
