# Proposal: protect-book-comic-assets

## 背景

漫画类电子书的章节图片现在会跟随 `/pc/book/getById` 和 `/pc/book/menus` 返回。未购买用户只要请求详情接口，就能拿到 `book_details[].pages[].imageUrl`，再直接访问对象存储签名地址。

这会绕过购买流程。详情页需要展示书籍信息和章节目录，但不应该把收费章节的图片地址一起吐出去。

## 目标

- 未购买、等级不足的用户不能从电子书详情或目录接口拿到收费漫画页图片地址。
- 免费章节仍可试读。
- 已购买用户、等级满足用户、管理端编辑场景保持可用。
- 阅读页继续通过章节内容接口拿图片，并沿用已有章节级权限校验。

## 非目标

- 本次不改 R2 bucket 权限、CDN 规则和对象生命周期。
- 本次不做水印、截图防护、DRM。
- 本次不改变购买下单流程。
- 本次不调整电子书页面样式。

## 用户影响

- 普通未购买用户仍能看详情和目录，但只能拿到免费章节图片。
- 付费/VIP/小班/内部成员/创始人按现有 `level` 规则读取内容。
- 管理员 `forEdit=true` 仍能拿原始图片路径用于编辑。

## 风险

- 兼容性风险：低。详情和目录接口仍返回章节，只是不再给无权限章节挂 `pages`。
- 数据风险：无数据库结构变更。
- 性能风险：低。复用已有购买关系和等级判断。
- 安全风险：降低未授权批量抓图风险，但无法阻止合法读者截图或二次转存。
- 回滚风险：回滚代码即可恢复原行为。

## 验收标准

- [ ] 未登录或未购买用户请求付费漫画书详情时，收费章节 `pages` 为空。
- [ ] 免费章节 `pages` 可正常返回，用于试读。
- [ ] 已购买用户或等级满足用户请求同一本书详情时，章节 `pages` 正常返回。
- [ ] `/pc/book/detail` 继续按章节权限返回漫画图片。
- [ ] 自动化测试覆盖上述关键场景。

## 关联信息

- 用户反馈：未付费用户可通过 `/pc/book/getById?id=1008` 直接拿漫画图片 URL。
