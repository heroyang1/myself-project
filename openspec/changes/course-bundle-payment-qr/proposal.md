# Proposal: course-bundle-payment-qr

## 背景

课程详情页需要在右侧展示与当前课程相关的上架套餐，并允许用户查看套餐详情后直接购买。恢复公共支付链路后，课程与套餐购买重新走旧版支付接口，导致二维码无法弹出。为避免影响电子书、会员、工具等其他支付模块，需要把修复范围限定在课程和套餐边界内。

## 目标

- 在课程详情页支持查询当前课程关联的上架套餐。
- 支持用户在课程详情页查看套餐详情并发起套餐购买。
- 恢复课程单品购买和套餐购买的支付二维码生成能力。
- 套餐封面使用套餐保存时的资源封面相对路径，并在 C 端返回可访问临时链接。
- 支付二维码修复限定在课程/套餐模块，不修改公共支付服务和其他业务模块。

## 非目标

- 本次不改造公共订单支付链路。
- 本次不修改电子书、会员、工具、秒杀等其他模块支付逻辑。
- 本次不新增数据库表结构。
- 本次不解决支付平台上游商户进件或子通道配置问题。

## 用户影响

- 普通用户在课程详情页可看到相关推荐套餐。
- 用户购买课程或推荐套餐时，应能正常弹出支付二维码。
- 套餐支付成功后，后端继续按套餐内容发放课程/电子书权益。
- 其他模块支付入口不受本次课程/套餐专用支付链路影响。

## 风险

- 兼容性风险：中。课程/套餐支付改为模块内专用 RSA jump 创建链路，但响应字段保持 `qrcode/payUrl/orderNo` 兼容前端。
- 数据风险：低。复用既有 `osh_order`、`osh_payment`、`osh_course_buy` 和套餐表，不新增表。
- 性能风险：低。推荐套餐按资源匹配并限制返回数量。
- 安全风险：中。RSA 私钥优先读取配置，开发环境可用本地私钥文件兜底，提交不包含密钥。
- 回滚风险：中。回滚后课程/套餐购买会重新依赖公共旧支付链路，可能再次无法生成二维码。

## 验收标准

- [x] 课程支付创建接口返回可用于二维码渲染的 `qrcode` 或 `payUrl`。
- [x] 套餐支付创建接口返回可用于二维码渲染的 `qrcode` 或 `payUrl`。
- [x] 公共 `PayConfig`、`PayServiceImpl`、`OrderServiceImpl` 不因本次修复产生改动。
- [x] 后端编译通过：`mvn -pl backstage-admin -am -DskipTests compile`。
- [ ] 重启本地 release 后端后，课程详情页课程购买和推荐套餐购买均能弹出二维码。

## 关联信息

- 后端接口：`/pc/course/pay/*`、`/pc/bundle/*`
- 后端模块：`controller/course`、`controller/bundle`、`service/impl/course`、`service/bundle`
- 前端页面：课程详情页推荐套餐与支付弹窗
