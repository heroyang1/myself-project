# Proposal: add-external-dependency-spec

## 背景

Harness 工程课程第 29~31 讲确定了外部依赖的三大解法细则（独立线程池 / 三层超时 / 熔断降级），
三段定稿的细则目前只存在于对话记录中，无单一事实源可查。AI 与新人编写外部调用代码时
（支付/物流/短信/HTTP 客户端）缺少可加载的规范层文档，红线晋升讨论（P6）也没有落纸的依据文本。

## 目标

- 将三段细则收拢为 `.harness/外部依赖规范.md`（三节：线程池 / 超时 / 熔断降级，每节开头写明"什么时候读"）
- 在 `CLAUDE.md` 第 3 层规范索引登记一行（内容 → 位置 → 何时装载），保持宪法 ≤100 行
- 为后续红线晋升决策（P6）提供判据文本

## 非目标

- 本次不晋升任何红线进 CLAUDE.md 第 2 层（由 P6 另行决定）
- 本次不修改任何 Java 代码、配置、DDL（纯文档新增）
- 本次不建设 paths 自动装载通道

## 用户影响

- 无终端用户影响；影响开发者与 AI 的编码时规范加载路径（新增一份可索引文档）。
- 不影响已有数据、缓存、权限。

## 风险

- 兼容性风险：无（纯文档）。
- 数据风险：无。
- 性能风险：无。
- 安全风险：无；文档不含密钥/内部端点。
- 回滚风险：无；删除两个文件与一行索引即可完全回滚。
- 治理风险：CLAUDE.md 加索引行会触行数税，须同次压缩一行引言，控制在 100 行内。

## 验收标准

- [ ] `.harness/外部依赖规范.md` 存在且三节齐全，每节首行有"什么时候读这份规范"
- [ ] `CLAUDE.md` 第 3 层新增索引行，总行数 ≤ 100
- [ ] 四件套非空，`bash scripts/verify-ai-process.sh` 通过
