# Proposal: product-bundle-management

## 背景

平台需要把课程、电子书、工具、考试等可售资源组合成套餐，用于运营活动、组合售卖和买主送副场景。原有后台缺少独立套餐管理能力，运营无法在不影响单品模块的情况下配置套餐、调整上下架状态和维护套餐内商品。

## 目标

- 新增后台套餐管理能力，支持套餐列表、详情、保存、上下架、删除。
- 支持两种售卖模式：`PRIMARY_GIFT` 买主送副、`FLAT_BUNDLE` 打包优惠。
- 支持在套餐模块内按资源类型搜索课程、电子书、工具、考试资源候选。
- 新增独立套餐表和套餐明细表，保存套餐基础信息与商品快照。
- 保持兑换码、课程、电子书、工具、考试等模块的既有逻辑不变。

## 非目标

- 本次不实现 C 端套餐购买入口和订单结算链路。
- 本次不改变单品课程、电子书、工具、考试的售卖逻辑。
- 本次不复用或修改兑换码模块资源 VO、Mapper 或接口契约。
- 本次不新增站内推荐、搜索索引或营销自动化能力。

## 用户影响

- `level>=5` 的后台用户可以进入套餐管理页面维护套餐。
- 运营可以通过资源搜索选择套餐商品，减少手填资源编号带来的错误。
- 已上架套餐不能直接删除，需要先下架，避免误删线上配置。
- 其他业务模块入口、接口和内部逻辑不受套餐模块影响。

## 风险

- 兼容性风险：低。新增 `/pc/admin/bundle/*` 接口，不修改既有接口。
- 数据风险：中低。新增 `osh_product_bundle`、`osh_bundle_item` 两张表，不迁移历史业务数据。
- 性能风险：低。列表与资源搜索均分页，资源搜索限制最大页大小。
- 安全风险：低。后台接口统一使用 `@OshUserLevel(5)`。
- 回滚风险：低。回滚代码后新增表可保留，不影响现有业务。

## 验收标准

- [x] 后台用户可以分页查看、筛选套餐列表。
- [x] 后台用户可以创建和编辑套餐，并至少添加符合售卖模式约束的商品。
- [x] 买主送副模式必须且只能有一个主商品，并至少有一个副商品。
- [x] 打包优惠模式至少包含两个商品。
- [x] 已上架套餐不能直接删除，必须先下架。
- [x] 资源搜索在套餐模块内实现，不依赖兑换码模块 VO 或 Mapper。
- [x] 前端套餐页面构建通过，用户已完成手动验收。
