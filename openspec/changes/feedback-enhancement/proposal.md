# Proposal: feedback-enhancement

## 背景

反馈模块目前缺少状态变更后的主动通知机制，用户提交反馈后无法及时获知处理进展。同时公告系统缺少 WebSocket 刷新广播能力，前端需要手动刷新页面才能看到新公告。此外，开源项目模块需要扩展功能以支持更丰富的展示，首页反馈热门字段存在冗余 VO 需要精简。

## 目标

- 新增反馈状态变更邮件通知，状态流转时自动通知提交者。
- 新增公告 WebSocket 刷新广播器，支持按模块/频道定向广播。
- 反馈点赞、收藏、动态 Service 交互逻辑优化。
- 公告 Mapper 扩展，支持按模块/频道灵活查询。
- 开源项目模块 Controller/Service 功能扩展。
- 精简首页反馈热门字段，移除冗余 HotFeedbackVO。

## 非目标

- 本次不新增数据库表（复用已有 `osh_announcement` 表）。
- 本次不改造前端 UI（前端 PR 独立提交）。
- 本次不实现反馈后台管理 CRUD。

## 用户影响

- 反馈状态变更时，提交者会收到邮件通知（含标题、状态详情、跳转链接）。
- 前端公告栏可通过 WebSocket 实时刷新，无需手动刷新页面。
- 开源项目展示信息更丰富（技术组件库信息、公告能力）。
- 首页反馈热门查询更轻量。

## 风险

- 兼容性风险：低。邮件通知和广播为增量副作用，失败不阻断主流程。
- 数据风险：低。复用已有表，无 schema 变更。
- 性能风险：低。邮件发送异步执行，广播走 WebSocket 通道。
- 安全风险：低。邮件仅发送给反馈提交者，广播不含敏感数据。
- 回滚风险：revert commit 即可。

## 验收标准

- [ ] 反馈状态变更后提交者收到邮件通知。
- [ ] 公告广播器发出 `ANNOUNCEMENT_REFRESH` WebSocket 消息。
- [ ] 反馈点赞/收藏/动态 Service 交互逻辑正常。
- [ ] 开源项目接口返回扩展字段。
- [ ] 首页反馈热门查询不再使用 HotFeedbackVO。
- [ ] `mvn compile` 通过，现有接口不受影响。
