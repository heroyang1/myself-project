# Proposal: unify-alipay-payment-only

## 背景

测试环境汇付接入后，支付宝扫码支付已跑通；微信扫码当前缺少可用的 PC Native 请求能力。为避免新订单继续误走微信或其他未验证通道，需要后端把新建支付请求统一兜底到支付宝，同时保持旧订单、旧回调和历史数据可查询。

## 目标

- 课程、套餐、电子书、工具等新建支付默认走支付宝。
- 后端兼容旧前端传入的 `wechat/wxpay/union` 等参数，统一归一为支付宝或返回明确错误。
- 汇付交易类型统一使用支付宝正扫 `A_NATIVE`。
- 保持支付成功回调、状态查询和权益发放逻辑兼容。

## 非目标

- 本次不接入微信官方 Native 支付。
- 本次不接入银联/云闪付。
- 本次不变更数据库表结构。
- 本次不改生产配置。

## 用户影响

- 新支付订单稳定生成支付宝扫码二维码。
- 旧订单查询和回调不受影响。
- 如果旧页面仍传微信参数，后端不会再走不可用的微信扫码通道。

## 风险

- 兼容性风险：历史代码中对支付方式字段存在微信默认值，需要统一归一。
- 数据风险：不改表结构，不批量修改历史订单。
- 性能风险：无新增重型查询。
- 安全风险：不提交任何支付密钥。
- 回滚风险：回滚代码即可恢复原多通道策略。

## 验收标准

- [ ] 课程支付传入空值、`wxpay` 或 `alipay` 时均能创建支付宝订单。
- [ ] 套餐支付传入空值、`wxpay` 或 `alipay` 时均能创建支付宝订单。
- [ ] 公共支付服务汇付下单使用 `A_NATIVE`。
- [ ] 后端编译通过。
