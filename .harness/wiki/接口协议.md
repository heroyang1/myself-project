# 接口协议

> **装载时机**：写/改 Controller、前后端联调、排"接口返回码不对"时读。
> 本文是知识库第 2 层。响应格式与前端对接的**正文事实源**是
> `docs/reference/api-spec.md` 与 `docs/reference/error-codes.md`——本文只做装载式摘要+陷阱登记。

## 1. 统一返回格式

- `AjaxResult extends HashMap`，键固定 `code / msg / data`；分页列表用 `TableDataInfo`。
- **HTTP 状态码恒 200**，业务成败一律看 `code`——用 HTTP 码表达业务失败 = 协议违例。
- 全局异常处理器兜底：业务异常不裸抛、未知异常不外泄堆栈（日志里留全栈，响应里只留码与话术）。
- DTO 校验：`@Validated` 缺失 = 零校验（案例集·案例11），Controller 上必挂。

## 2. 路径公约（实扫登记）

- C 端统一 `/pc/**` 前缀；B 端管理侧 `/pc/admin/**`。
- `/pc` 前缀被认证 Filter 拦截：公开接口须 `@Anonymous`，否则 401（陷阱实录）。
- ⚠️ 路径英文名存在历史漂移（`/pc/user_test`=考试、`/pc/order/flashsale`=秒杀、
  `/pc/user_coupon`=券）——**新接口命名以领域术语.md 正名为准，不改存量路径**。

## 3. 认证双体系

| 端 | 注解 | 身份 |
|---|---|---|
| B 端 | `@PreAuthorize("@ss.hasPermi('模块:资源:操作')")` | SysUser |
| C 端 | `@OshUserLevel(N)` 或 `@Anonymous` | OshUser(userId) |

- 混用即事故：C 端挂 B 端注解 → 403（案例集·案例5）；多角色判断只查单角色 → VIP 误拦（案例6）。
- 注解固定顺序（从上到下）：`@ApiOperation` → 权限注解 → HTTP 方法注解。
- HTTP 方法语义：GET 查询 / POST 新增与导出 / PUT 修改 / DELETE 删除。

## 4. 模块与接口清单（按域分组·实况登记）

> 与"契约预设"相反：本仓库代码既成，此处登记**实际路径骨架**，接口明细进对应 Controller 读。

| 域 | Controller（backstage-system） | 根路径 |
|---|---|---|
| 订单 | OshOrderSaveController / OshOrderListController / OshLearnController | `/pc/order/save`、`/pc/order`、`/pc/order/learn` |
| 支付 | PayController / WxPayController / HuifuPayNotifyController | `/pc/pay`、`/pc/order/wxpay`、`/pc/pay/huifu`（回调） |
| 秒杀 | OshFlashsaleListController（⚠️ 别名存量） | `/pc/order/flashsale` |
| 拼团 | GroupController | `/pc/group` |
| 服务人员分组 | OshGroupServerController（⚠️ 与拼团同前缀，靠子路径区分） | `/pc/group` |
| 课程/套餐 | CoursePayController / BundleController / AdminBundleController | `/pc/course/pay`、`/pc/bundle`、`/pc/admin/bundle` |
| 用户 | OshUserController / UserRedeemController | `/pc/user`、`/pc/user/redeem` |
| 内容/其他 | 网站、问答、考试、首页等 | 各自 `/pc/**`，实扫为准 |

## 5. 回调契约（支付）

- 入口校验三件套：**签名、金额（对实付总额）、提供方**，任一不过即拒。
- 幂等：payment 已 SUCCESS 的重复回调直接分发 handler，不重复推进状态。
- 未注册 productType 的处置：现状抛异常（会引发网关重试风暴），目标改告警登记——改动须立 change。
